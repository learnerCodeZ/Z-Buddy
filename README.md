1. **下载桌宠应用** → <https://github.com/learnerCodeZ/Z-Buddy/releases/latest>
   （`Z-Buddy_0.1.0_x64-setup.exe` 安装版，或 `z-buddy-app.exe` 免安装版。未做代码签名，SmartScreen 弹窗时点"更多信息 → 仍要运行"）

## 这是什么

一只挂在桌面角落的像素小宠物。你用 ZCode 干活时，它实时反映 Agent 的状态：干活时打字、出错时沮丧、完成时庆祝、深夜冒 Zzz 气泡睡觉——**对标 OpenAI Codex 的 Pet Mode，但为 ZCode 而生**。

它不只是状态动画。Z-Buddy 的野心是成为 **Agent 在物理世界的化身**：

- 🔍 **看得见**：ZCode 操控你的电脑时（无障碍后台操作），桌宠用点击动画 + 目标元素高亮框 + 气泡旁白把"隐形操作"演出来；
- 🤝 **能协作**：你随时可以接管——帮它点两步，停手后它自动接上（人机接力协议：让位 → 交接 → 复位）；
- 💬 **会聊天**：点一下宠物，直接和 GLM 对话。它知道你刚跑了个失败的任务，说话像活的，不像挂皮聊天机器人；
- 📋 **可查询**：鼠标悬停展开后台任务面板——有哪些任务、进行到第几步、等不等你审批，一目了然。

## 为什么做

| 缺口 | 现状 |
|---|---|
| 生态缺口 | Codex 有桌宠且有 4600+ 社区宠物包的生态；ZCode 官方没有桌宠功能 |
| 信任缺口 | ZCode 的电脑操作多为无障碍后台执行，屏幕上什么都看不到 |
| 协调缺口 | 人机同时操作电脑时，没有任何"用户优先"的门控机制 |

## 架构

```
┌──────────────────────────┐         ┌──────────────────────────────┐
│  ZCode 插件 (z-buddy)     │         │  Z-Buddy 桌宠应用（独立进程）  │
│                          │         │                              │
│  hooks ── 生命周期事件     │──文件──▶│  悬浮窗（置顶/无边框/可拖动）   │
│  skill ── 宠物包生成(规划) │ 600ms轮询│  精灵图播放器（状态→动画行）    │
│  MCP ──── 操作权证(设想)  │         │  多会话聚合 / 预警气泡          │
│                          │         │  后台任务面板(规划)             │
└──────────────────────────┘         └──────────────────────────────┘
         数据面：~/.z-buddy/{state.json, sessions/, events.jsonl, pause}
```

> 📐 插件侧目录结构**完全遵循 ZCode 官方模板插件 [Example Plugin](https://github.com/zai-org/zcode-plugins) 的推荐布局**（`.zcode-plugin/plugin.json` manifest + `hooks/hooks.json` + Skills + MCP 预留位），与官方插件市场规范保持一致，为上架做好准备。

## 路线图

- ✅ **Phase 0 · 技术验证**：hooks 事件流实测、打断行为实验、暂停机制原型、Electron/Tauri 选型对拼
- ✅ **Phase 1 · MVP**（v0.1.0 已发布）：状态动画、悬浮窗、暂停拦截、宠物包格式、自动更新、官网与文档
- 🔨 **Phase 2 · 聚合与预警**（已完成待发版）：多会话聚合、computer use 识别与预警气泡、体验修缮包
- 🔜 **Phase 3 · 生态与分发**：宠物包规范与 UGC、推广、官方插件市场收录、多平台、代码签名
- 🔬 **Phase 4 · 护城河**：人机接力、审批卡片、子代理多宠物、GLM 对话、养成系统

## 原则

1. **无侵入**：桌宠挂了绝不能影响 ZCode 正常工作（Hook 静默降级）；
2. **隐私**：聊天历史只存内存不落盘；数据只在用户主目录，永不进项目文件夹；
3. **版权**：自带宠物全部原创；宠物包格式兼容开放格式，但分发渠道拒绝 IP 侵权内容；
4. **透明**：AI 在干什么，用户永远看得见。
